# Code Review Skill

name: code-review

## Task
代码质量审查和安全审计，提供可执行的改进建议。

## Review Checklist

### 1. 安全问题 (Security) - 最高优先级
- [ ] SQL 注入风险
- [ ] XSS 跨站脚本
- [ ] CSRF 跨站请求伪造
- [ ] 认证/授权漏洞
- [ ] 敏感数据泄露（密码、密钥、PII）
- [ ] 不安全的反序列化
- [ ] 路径遍历漏洞
- [ ] 命令注入风险

### 2. 代码质量 (Code Quality)
- [ ] 命名规范（变量、函数、类）
- [ ] 函数长度和复杂度
- [ ] 代码重复
- [ ] 注释质量和必要性
- [ ] 代码格式一致性

### 3. 性能问题 (Performance)
- [ ] 低效循环和查询
- [ ] 缺失缓存机制
- [ ] 内存泄漏风险
- [ ] 不必要的计算
- [ ] 数据库查询优化

### 4. 可维护性 (Maintainability)
- [ ] 模块化和职责分离
- [ ] 依赖管理
- [ ] 配置外部化
- [ ] 错误处理一致性
- [ ] 日志记录

### 5. 测试覆盖 (Testing)
- [ ] 单元测试存在性
- [ ] 边界条件测试
- [ ] 错误场景测试
- [ ] 集成测试

## Workflow

### Phase 1: 理解代码
1. 读取目标文件和相关上下文
2. 理解代码功能和设计意图
3. 识别关键逻辑路径

### Phase 2: 逐层审查
1. 安全扫描（优先）
2. 代码质量分析
3. 性能热点识别
4. 可维护性评估

### Phase 3: 生成报告
1. 问题分级（Blocker/High/Medium/Low）
2. 提供具体修复代码
3. 给出优先级建议

### Phase 4: 验证建议
1. 确保修复建议可执行
2. 验证不破坏现有功能
3. 提供测试建议

## Issue Severity Definitions

| 级别 | 定义 | 响应时间 |
|------|------|----------|
| **Blocker** 🔴 | 安全漏洞、严重 bug、数据丢失风险 | 立即修复 |
| **High** 🟠 | 功能缺陷、性能问题、严重代码异味 | 24-48 小时 |
| **Medium** 🟡 | 代码质量、可维护性问题 | 下次迭代 |
| **Low** 🟢 | 风格问题、优化建议 | 有时间时 |

## Rules

1. **安全第一**: 安全问题永远是最高优先级
2. **建设性反馈**: 指出问题的同时提供解决方案
3. **具体定位**: 精确到文件：行号
4. **可执行建议**: 修复代码必须可直接使用
5. **平衡批评**: 也要指出代码亮点
6. **上下文感知**: 考虑项目规模和阶段
7. **避免过度工程**: 建议要适合项目实际需求

## Tools Used

- `read` - 读取代码文件
- `exec` - 运行 linter/测试（如配置）
- `write` - 保存审查报告
- `sessions_spawn` - 复杂项目可启动子代理专项审查

## Language Support

优先支持：
- JavaScript/TypeScript
- Python
- Go
- Java
- Rust
- Shell/Bash

其他语言可审查通用问题（安全、结构、注释等）。

## Notes

- 大型项目建议分模块审查
- 可配合 linter 工具使用（eslint, pylint 等）
- 敏感代码审查注意保密
