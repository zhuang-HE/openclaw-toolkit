# Documentation Skill

name: documentation

## Task
技术文档生成和维护，创建清晰、完整、可维护的文档。

## Document Types

### 1. API 文档
- 端点说明
- 请求/响应格式
- 参数详解
- 错误码说明
- 使用示例

### 2. 架构文档
- 系统概述
- 组件图
- 数据流
- 技术选型说明
- 部署架构

### 3. 使用教程
- 快速开始
- 安装指南
- 配置说明
- 常见问题
- 最佳实践

### 4. Changelog
- 版本历史
- 新增功能
- Bug 修复
- 破坏性变更
- 迁移指南

### 5. README
- 项目简介
- 功能特性
- 安装使用
- 贡献指南
- 许可证

## Workflow

### Phase 1: 信息收集
1. 读取源代码和现有注释
2. 分析项目结构和依赖
3. 识别关键接口和模块
4. 收集配置和部署信息

### Phase 2: 内容提取
1. 提取函数/类签名和类型
2. 识别输入输出规范
3. 整理配置项和环境变量
4. 记录依赖和前置条件

### Phase 3: 文档生成
1. 选择合适模板
2. 填充结构化内容
3. 添加代码示例
4. 生成图表（如需要）

### Phase 4: 质量检查
1. 验证信息准确性
2. 检查链接有效性
3. 确保格式一致性
4. 审查可读性

## Rules

1. **准确性优先**: 文档必须与代码实际行为一致
2. **示例驱动**: 每个重要概念都要有代码示例
3. **层次清晰**: 从概述到细节，层层深入
4. **搜索友好**: 使用标准术语，便于搜索
5. **版本标注**: 标注文档对应的代码版本
6. **多语言支持**: 技术术语保留英文，解释用中文
7. **可维护性**: 文档结构便于后续更新

## Writing Principles

### 清晰性 (Clarity)
- 使用简单直接的句子
- 避免歧义和模糊表述
- 一个段落一个主题

### 完整性 (Completeness)
- 覆盖所有公开 API
- 包含错误处理说明
- 提供故障排除指南

### 一致性 (Consistency)
- 术语使用一致
- 格式风格统一
- 代码示例风格一致

### 实用性 (Practicality)
- 提供真实可用的示例
- 包含常见场景
- 给出最佳实践建议

## Tools Used

- `read` - 读取源代码
- `glob` - 查找相关文件
- `exec` - 运行文档生成工具
- `write` - 创建/更新文档
- `browser` - 参考类似项目文档

## Documentation Standards

### 代码注释
```javascript
/**
 * [函数功能简述]
 * 
 * @param {type} name - [参数说明]
 * @returns {type} [返回值说明]
 * @throws {type} [异常说明]
 * 
 * @example
 * ```javascript
 * const result = functionName(arg1, arg2);
 * ```
 */
```

### Markdown 规范
- 使用 `##` 作为主章节
- 代码块标注语言类型
- 表格对齐便于阅读
- 链接使用相对路径（项目内）
