# Memory Consolidation Skill

name: memory-consolidation

## Task
定期整理和压缩记忆，将短期日志提炼为长期记忆，保持记忆系统高效。

## Why This Matters

就像人类需要睡眠来巩固记忆一样，AI 助手也需要定期：
1. **提炼精华**: 从日常日志中提取重要事件
2. **删除噪音**: 移除过时和冗余信息
3. **建立连接**: 关联相关记忆形成知识网络
4. **优化存储**: 保持记忆系统高效可检索

## Workflow

### Phase 1: Orient（定位）
1. 读取当前 MEMORY.md
2. 扫描 memory/ 目录文件
3. 识别时间范围（默认最近 7 天）
4. 确定整理优先级

### Phase 2: Gather（收集）
1. 读取每日 memory/YYYY-MM-DD.md 文件
2. 提取关键事件和决策
3. 识别重复模式和主题
4. 标记需要长期保留的内容

### Phase 3: Consolidate（整合）
1. 将新记忆归类到 MEMORY.md 适当章节
2. 更新现有记忆的上下文
3. 建立记忆之间的连接
4. 记录学习和洞察

### Phase 4: Prune（修剪）
1. 归档超过 30 天的日志
2. 删除重复和过时信息
3. 压缩已整合的内容
4. 保持目录清爽

## Consolidation Rules

### 保留原则
✅ **保留**:
- 用户明确说"记住这个"的内容
- 重复出现的模式和主题
- 影响未来决策的经验教训
- 项目关键里程碑和决策
- 技能和能力的重大更新

❌ **不保留**:
- 一次性任务细节
- 临时性信息（已过期）
- 重复的日常日志
- 已被更新替代的信息
- 过于琐碎的交互细节

### 提炼原则
1. **从具体到抽象**: 提取通用原则
2. **从事件到模式**: 识别重复模式
3. **从孤立到连接**: 建立记忆关联
4. **从冗长到精炼**: 压缩为要点

### 组织原则
1. **主题分组**: 相关内容放在一起
2. **时间标记**: 重要事件标注时间
3. **优先级标注**: 高优先级内容置顶
4. **交叉引用**: 相关记忆互相链接

## Trigger Conditions

### 自动触发
- 每日 heartbeat 检查（低优先级）
- memory/ 目录超过 7 个文件
- MEMORY.md 超过 50KB

### 手动触发
- 用户请求整理记忆
- 项目里程碑完成
- 重大决策后

## Tools Used

- `read` - 读取记忆文件
- `write` - 更新 MEMORY.md
- `exec` - 文件归档操作
- `glob` - 查找记忆文件

```

2. 提取关键事件和决策

```

```
2. 提炼项目教训和最佳实践

5. 记录可复用模式
```

## Memory Health Metrics

| 指标 | 健康范围 | 说明 |
|------|----------|------|
| MEMORY.md 大小 | 20-100KB | 过大需压缩 |
| 未处理日志 | <7 天 | 超过需整理 |
| 归档文件 | 按需 | 定期清理 |
| 记忆更新频率 | 每周 1-2 次 | 避免过度 |

## Notes

- 整理过程保留原始文件（先备份后归档）
- 用户可随时查看归档文件
- 敏感信息整理时注意保密
- 整理报告便于追溯变更
